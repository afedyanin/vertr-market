# Задание 001

## Контекст

* есть несколько потоков сигналов 
* каждый сигнал можно представить как пару значений: метка времени (DateTime), значение (double)
* каждому типу сигнала в системе ставится в соответствие index (int)
* в системе есть группа потоков (threads), которые одновременно принимают и регистрируют сигналы (signals)
* каждый поток отвечает за свой диапазон индексов, соотвествующий набору типов сигналов
* в системе присутствует доступный для всех потоков массив значений сигналов
* каждый поток, работая параллельно с другими потоками, записывает значение сигнала в этот массив по известному ему индексу
* отдельный сервис через равные промежутки времени делает копию (снепшот) массива сигналов и сохраняет его в объект MarketDataEvent

## Постановка задачи

### 1. Разработать класс - хранилище массива сигналов - SignalManager

* Класс должен обеспечивать доступ из различных потоков к массиву значений сигналов
* Давать возможность различным потокам записывать значения сигнала по индексу
* Каждый поток записывает только свой диапазон индексов
* Если в заданном интервале пришло несколько сигналов с одним и тем же индексом - оставлять только последнее значение
* В момент генерации снепшота обеспечить конситентность: данные, собранные из одного интервала времени не должны попадать в другой интервал
* После генерации снепшота обеспечить очистку данных в массиве
* Разместить класс в сборке Vertr.Market.Application
* Написать unit-tests для класса SignalManager, проверяющие, в том числе возможности конкуретного доступа и консистентности данных


### 2. Разработать сервис MarketDataPeriodicService

* Класс, который в бесконечном цикле с помощью PeriodicTimer генерирует событие таймера
* При наступлении события таймера обращается к SignalManager и делает снапшот массива значений
* Снапшот сигналов сохраняет в поле объекта MarketDataEvent
* На момент снапшота необходимо обеспечить атомарность данных в массиве: значения сигналов из другого интервала времени не должны попадать в снапшот
* Разместить класс в сборке Vertr.Market.Application
* Написать unit-tests для класса MarketDataPeriodicService, проверяющие, в том числе возможности конкуретного доступа и консистентности данных

### 3. Условия и ограничения

* Использовать zero-allocation подход
* Использовать примитивы C#: `ArrayPool<T>`, `Span<T>`, `Memory<T>`
* Использовать lock-free подход для копирования массивов
* Использовать ref readonly struct, где это возможно
