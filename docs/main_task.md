# Разработка высокопроизводительного In-Memory Key-Value кэша

## Описание/Пошаговая инструкция

### Проектирование (System Design):

1.1. Спроектируйте архитектуру вашего сервиса.

1.2. Определите ключевые компоненты: сетевой уровень, парсер протокола, конвейер обработки, ядро хранилища.

1.3. Опишите их взаимодействие.

Реализация ядра: Создайте потокобезопасный класс для хранения данных. Используйте ReaderWriterLockSlim для эффективного доступа и Interlocked для сбора статистики.

Реализация сетевого уровня: Напишите асинхронный TCP-сервер, используя System.Net.Sockets или System.IO.Pipelines. Примените ArrayPool для работы с буферами.

Реализация протокола: Создайте zero-allocation парсер команд на основе Span.

Интеграция: Свяжите все компоненты в единое работающее приложение.

### Тестирование и оптимизация:

2.1. Напишите бенчмарки для критических частей кода (например, парсера) с помощью BenchmarkDotNet.

2.2. Проведите нагрузочное тестирование вашего сервера с помощью NBomber.

### (Опционально) Продвинутые возможности:

3.1. Реализуйте кастомный сериализатор с помощью Source Generators.

3.2. Интегрируйте OpenTelemetry для сбора метрик и трассировок.

3.3. Добавьте базовые механизмы безопасности.

### Документация: Создайте README.md файл в вашем репозитории.

## Критерии оценки:

Для принятия проектной работы необходимо выполнить одно из условий: защитить проект на занятии или предоставить собственную видеозапись защиты.
Проект оценивается по системе «зачтено» / «не зачтено». 
Балльная оценка используется только для внутренней проверки соответствия требованиям и не указывается в сертификате.

Минимально необходимые требования:

- Реализована базовая функциональность: сервер принимает подключения и корректно обрабатывает команды SET, GET, DELETE.
- Хранилище данных является потокобезопасным, используется ReaderWriterLockSlim.
- Парсер команд реализован с использованием Span для минимизации аллокаций.
- Сетевой уровень использует ArrayPool для эффективной работы с буферами.
- Проект содержит сценарий нагрузочного тестирования на NBomber.
- В репозитории присутствует README.md файл с описанием проекта и результатами тестов.

Для высокой оценки от экспертов (не указывается в сертификате):
Реализована как минимум одна продвинутая возможность: Source Generators, OpenTelemetry или механизмы безопасности.
